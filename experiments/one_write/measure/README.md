# measure/ — замеры ставки «один проход вместо эпох» на ЕГО модели и корпусе

Всё считается на его `leancore` (копия лежит вне репозитория, путь переопределяется):

```
export LEANCORE=~/AIra/leancore          # должен содержать nano_lc.py, data/prep/*, results/ckpt_L_mussa1500s1.npz
export AIRA_CACHE=~/run1/cache           # кэш представлений H (делает rebind_cache_dmg.py)
python3 gate.py                          # 12 с  → гейт: 111.21 (его метрика) / 112.37 (полный свип)
python3 rebind_cache_dmg.py              # ~7 мин → §1–§3: урон, oracle-копия, Adam-эпохи, кэш H
python3 rebind_closed_form.py          # ~5 мин → §3: замкнутый попозный ridge с приором (0 эпох)
python3 rebind_state.py                # ~4 мин → §4: RLS vs Adam на реальных k→v (потолок 21%)
python3 rebind_lowrank_channel.py      # ~4 мин → §4: аддитивный низкоранговый канал, α*=0
python3 rebind_knn.py                    # ~1 мин → §3: retrieval-канал (2-gram счётчик), оба контроля
```

Числа, которые обязаны воспроизвестись (иначе обвязка врёт — ничего не выводить):

| скрипт | контрольное число |
|---|---|
| `gate.py` | `111.21` (6 окон, seed 1234), `112.37` / `nll 4.7218` (полный свип) |
| `rebind_cache_dmg.py` | урон `sel 9.9720`, `Δ +2.0946`; oracle-копия `возврат 100.0%`, `all 4.7218` |
| `rebind_closed_form.py` | `ridge m=4 μ=100 → 75.6%`; `ridge m=8 μ=1000 → 148.9%` (all 5.08) |
| `rebind_state.py` | `ridge 0.790592`, `RLS 0.790593`, `‖ΔW‖/‖W‖ = 1.1e-04` |
| `rebind_knn.py` | чистый контроль: `all 4.7221 → 4.7070` (PPL 112.37 → 110.66) |

Модель: `NanoGPT(V=8000, D=192, L=4, ff=576, kind="ema")`, 2 591 616 парам, `--muon`,
sampled softmax K=512, 1500 шагов, `results/ckpt_L_mussa1500s1.npz`.
Корпус: 1 011 399 train / 64 557 val, `data/prep` (word-v8000, Шекспир + Paradise Regained).

Что НЕ делать при переносе на GPU:
* не мерить Δnll усреднением по корпусу (покрытие задетых позиций 5.6% ⇒ эффект тонет);
* не решать голову LS «в one-hot» (cond `HᵀH` = 9.6e8, решение схлопывается в 0);
* не давать Adam lr=1e-2 на строках E (`‖E‖row = 0.36`, шаг ~2.0 ⇒ дивергенция);
* не путать порядок ключа `(prev2, prev1)` в retrieval-таблице — переставленный ключ даёт
  «покрытие 56%» и ровно вред, что выглядит как опровержение метода.
