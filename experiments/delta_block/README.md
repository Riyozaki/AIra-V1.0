# delta_block — эталон+чанк трёх миксеров для LeanCore

См. `docs/06-DELTA-BLOCKS.md` (диагноз, таблица стоимости, ожидания, план брекета).

- `lc_delta.py` — `dddecay` / `rot` / `delta`: рекуррентный ЭТАЛОН (цикл по T) с
  аналитическим backward; для `dddecay` и `rot` — чанк-формы (`*_fwd_chunked`), которые
  обязаны совпадать с эталоном. `cost_per_token` / `params_per_block` — чтобы A/B равнял
  стоимость, а не «у кого блок жирнее».
- `test_delta.py` — три проверки в духе MATH.md §11: конечные разности (float64, ε=1e-6,
  относительная метрика), «чанк за чанком == целиком», чанк-форма == эталон (включая
  float32), устойчивость δ-правила на T=2048. Выход 0 = всё сходится.

    python3 test_delta.py

Статус (замерено здесь, numpy 2.4.6, 2026-09-01): **exit 0** — FD ≤ 1.3e-09,
чанк-паритет ≤ 6.7e-16, float32 чанк-vs-рекурр ≤ 1.2e-07, δ-правило конечно при T=2048
и `|S|max = 1.01` (не растёт).

Качество на корпусе здесь НЕ измеряется: PPL/iso-cost — только в его брекете на Kaggle T4
(`configs/lab/arms-leancore.json` переносится в `kaggle/bracket.py` как есть).

Чего здесь сознательно нет: WY-чанка для `delta` (без него arm нельзя учить — формула в
`docs/06` §4.1), бэкенда torch/cupy, и вообще любой оптимизации «в обход спецификации»:
этот файл — эталон, по которому надо сверять быстрые ядра.
