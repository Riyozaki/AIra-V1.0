# 03. Эксперименты

Три независимых трека. Трек E0 обязателен и первее остальных: без него E1/E2
неопровергаемы.

---

## E0. Стенд измерений (1–2 дня)

**Цель:** одна команда, которая выдаёт `ток/с`, `байт/токен`, `Дж/токен`, `занятая память` по
любой конфигурации, и пишет это в append-only журнал с hash конфигурации.

Состав:
1. `tools/hwprobe.py` — фактическая полоса DRAM/HBM, RAM, GPU, RAPL-счётчики (уже в репо).
2. Скрипт-обёртка над `llama-bench`/`vllm bench`, которая одновременно крутит
   `nvidia-smi --query-gpu=power.draw,utilization.gpu -l 0.2` или читает RAPL,
   и считает интеграл по времени → кВт·ч на прогон.
3. Фиксированные наборы: `pp ∈ {512, 4096, 32768, 131072}`, `tg = 256`, 3 повтора,
   медиана; температура/кузова зафиксированы (проветрить, лимит мощности записать).
4. `out/runs.jsonl` — одна строка = один прогон (конфиг, машина, версия, git hash, метрики).

Готовность: два прогона разных квантов дают стабильно (разброс повторов <3%) разные
`Дж/токен`, и вы можете объяснить разницу числом `B_tok` из формулы. Если объяснения
нет — измерение врёт (чаще всего: фоновый процесс, power-cap, первая итерация с cold cache).

## E1. Архитектурная микро-лаборатория (2–6 недель, высокий разброс)

**Зачем:** единственная территория, где соло-исследователь объективно быстрее лаборатории —
потому что лаборатории не интересен режим «300M–1.6B, 10B токенов, 24 ГБ, честные 3 сида».
Здесь у вас полный контроль переменной.

**Дизайн (жёсткий, иначе бесполезно):**
- Стенд: форк `karpathy/nanochat` (или `modded-nanogpt`) — НЕ свой трейнер.
  Он уже содержит Muon, value embeddings, скалярно-гейченные скипы, FA3 с
  чередующимся window-паттерном, WSD-расписание, Chinchilla-вывод гиперпараметров
  из одного `--depth`. Всё это — проверенные на масштабе куски, и ваш прирост
  обязан быть *сверх* них, а не вместо.
- **Базовая точка:** д20–д24, `10B` токенов FineWeb-Edu (или SmolLM-корпус),
  ~1 ч на 8×H100 либо эквивалент по FLOPs на вашем железе; метрика — валидационная
  перплексия + CORE (если успеете) + **Дж на шаг** и **пиковая память**.
- **Армы (по одной гипотезе на арми, всё остальное идентично, 3 сида):**

| # | Гипотеза | Ожидаемый эффект | Стоимость |
|---|---|---|---|
| 1 | Muon vs AdamW (контроль воспроизводимости) | +5–10% скорости сходимости | 2 прогона |
| 2 | Гибрид линейного внимания при 3:1 и 5:1 против 0:1 | −30..−60% памяти, ≈качество | 4 прогона |
| 3 | **KDA × MoR**: рекурсивный общий блок + линейные слои | −25% FLOPs, = качество | 4 прогона |
| 4 | Тернарный FFN (BitLinear) в 50% слоёв | −память, −энергия | 3 прогона |
| 5 | Per-layer embeddings (PLE) вместо полных эмбеддингов | −RAM при инференсе | 2 прогона |
| 6 | Адаптивная глубина по «энтропии токена» (гейт на шаг) | −20% FLOPs при +0.2 ppl | 3 прогона |
| 7 | EXP3/ReLU² vs SwiGLU при равном байт-бюджете | ±1% | 2 прогона |

- **Критерий принятия:** арма живёт, если при равном *энергетическом* бюджете
  (не FLOPs!) валидационная перплексия ниже на ≥3σ повторов, либо равна при
  ≥1.15× меньших `Дж/шаг`. Иначе — negative result в `docs/RESULTS.md`, и арма закрывается.
- **Статистика:** 3 сида, bootstrap CI по 10K, никаких «один прогон — и вау».
  Различия <1% на этом масштабе — шум, а не открытие.
- **Стоимость:** 60–200 GPU·часов всего. На 24 ГБ это 1.5B-модель ~2–6 ч за прогон,
  т.е. неделя на 20 прогонов. Реально.

**Побочный, но ценный результат:** таблица «что из speedrun-трюков переносится на
потребительское железо с сохранением эффекта». Она полезна всем и цитируется.

## E2. Студент домена + ночная консолидация (1–3 недели)

**Цель:** доказать, что `Ψ` (полезность на Джоуль) растёт от данных и политики записи
сильнее, чем от архитектуры.

Шаги:
1. **Корпус.** 5–20K промптов из ваших реальных сессий (код/исследования/агентские вызовы).
   Дедуп 8-грамами против eval-задач (иначе самообман), отбор по s1-принципам:
   difficulty (пропуск через текущую модель, оставить p∈[0.05,0.9]), diversity
   (кластеризация/таксономия), quality (верификация ответа тестом или судьёй).
2. **Учитель:** открытый 30–40B A3–A4B (не API — см. юридическую строку в 01-LEVERS).
3. **Обучение:** SFT 1–2 эпохи → on-policy distillation (reverse-KL) до плато;
   RLVR только на подмножестве с автотестом. Формат: LoRA r=16–64 → слияние.
4. **Базовая линия-убийца:** тот же студент **без** дистилляции и **с** RAG по тому же корпусу.
   Если ваш вклад не побеждает честный RAG-бейзлайн — вклад не в весах, а в данных,
   и это тоже результат (и он дешевле).
5. **Ночная консолидация:** накопление эпизодов → отбор по «surprise» (перплексия
   модели на исходе + факт успеха/провала) → курация в 50–500 пар → LoRA-шаг →
   регресс-тест (≥200 задач) → fuse или откат. Оценка: прирост решения задач
   после N ночей, приращение Дж/задача, число откатов.
6. **Метрика-сюрприз:** доля задач, решённых *без* обращения к длинному контексту
   (скилл выучен) — это ваш «мозговой» эквивалент: знание в весах/файлах, а не в KV.

Бенчмарки для сверки с полем (не для тщеславия, а чтобы вас цитировали):
MemoryBench, SkillLearnBench, AFTER (HF: `DavydenkoGr/AFTER`), LoCoMo, LongMemEval, BEAM.

## E3. Быстрые проверки-разведка (по 2–6 часов, делаются в первую очередь)

| # | Проверка | Решение «делать/не делать» |
|---|---|---|
| 1 | `-ncmoe` скан + 3 уровня кванта на 35B-A3B | >1.3× к ток/с? → брать |
| 2 | MTP/spec `--spec-draft-n-max 2..3` | acceptance ≥0.5? → брать |
| 3 | KV q8_0 vs f16 на 128K | ×2 полос при <1% качества? → брать |
| 4 | Инвариантный префикс промпта + `--cache-reuse` | ×N на агентской сессии? → переписать промпт-шаблон |
| 5 | BitNet-2B на CPU vs 3B-Q4 на dGPU (Дж/токен) | где меньше? → выбор «всегда-он» ветки |
| 6 | Каскад S1→S2 на 300 задачах | `p_easy ≥ 0.6`? → в продакшн, иначе в E2 |
| 7 | Гейт по энтропии vs гейт по «первый tool-call упал» | какой даёт меньше эскалаций при равном качестве |

## Правила, без которых всё это бесполезно

1. Одна гипотеза — одна арма — три сида. Смесь двух изменений = не результат.
2. Фиксировать в прогоне: git hash, версия либы, версию драйвера, лимит мощности,
   температуру, длину контекста, шаблон промпта, сида,параметры сэмплирования.
3. Никаких улучшений «на глаз» в проде без повтора бенча: `04-BENCH.md` B1 обязателен
   до и после.
4. Negative result публикуется в тот же день в `docs/RESULTS.md`. Люди, которые
   не публикуют неудачи, переделывают их повторно через полгода (это и есть
   главный расход соло-исследователя).
