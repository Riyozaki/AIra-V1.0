Дата: 2026-09-01. Код: `experiments/delta_block/{lc_delta.py,test_delta.py}`.
Контекст: всё ниже — про `leancore/nano_lc.py` в `Riyozaki/AIra` (его измеряемая система),
а не про «ещё одну архитектуру». Новизны в смысле статьи здесь нет; новизна в том, что
это **самый дешёвый неизвестный ему рычаг** и он влезает в уже готовый брекет.

## 0. Диагноз одной строки

```python
# nano_lc.py, ~стр. 268 (емю)
a = sigmoid(th)          # th — ПАРАМЕТР, не функция входа
h = a * h + (1 - a) * x  # time-invariant, без content-based правки
```

Это самый слабый член семейства S4-diag / RetNet: затухание не зависит от содержимого,
состояние не умеет ни «забыть по ключу», ни «прокрутиться». При этом он стоит 2·D MAC
на токен = **0.15 %** от его 258 048 MAC/токен блока. То есть апгрейд миксера почти
бесплатен по FLOPs — и именно поэтому он не сделан: нечего терять, есть что взять.

Его же собственные числа (MATH/README): EMA-блок против attention — ×3.11 дешевле по
MAC, ×2.4–2.6 изо-качество по цене обучения. Вся эта прибыль получена **самым примитивным
рекуррентом**. Ниже — три шага вверх по шкале «сколько памяти за какой ценой».

## 1. Руки

| arm | правило | чинит | MAC/токен | состояние | Δпараметров/блок |
|---|---|---|---|---|---|
| **CTRL** `ema` | `h_t = σ(th) h_{t−1} + (1−σ(th)) x_t` | — | 2D = 384 | D | — |
| **A** `dddecay` | `a_t = σ(W_a x_t + b)`, то же правило | data-dependence | D²+3D = 37 440 | D | +D²+2D = +37 056 |
| **B** `rot` | `h1,h2 ← ρ·R(w)·h + g·x` (комплексная диагональ) | фаза / state-tracking | 8D = 1 536 | 2D | +D = +192 |
| **C** `delta` | `S_t = α_t(I−β_t k_t k_tᵀ)S_{t−1} + β_t k_t v_tᵀ` | content-based запись/стирание | 8D² = 294 912 | D² | +4D²+… = +147 456 |

D=192. Для сравнения: `attn` при T=96 = 221 184 MAC/токен, при T=1024 = 933 888.

Отношение к attention (это и есть дизайн брекета):

| | к attn @T=96 | к attn @T=1024 |
|---|---|---|
| A `dddecay` | **0.169×** | 0.040× |
| B `rot` | **0.007×** | 0.002× |
| C `delta` | **1.333×** | 0.316× |

Вывод, который меняет план: **A и B — «почти бесплатно» при любом T; C при T=96 дороже
attention и имеет смысл только в длинном контексте** (T≥512), где как раз и maximal
преимущество без-attention-класса по его §4 (перелом T≈384 против проекций, T≈960 против
всего блока). Не совать `delta` в текущий брекет на T=96 — это arm с худшим ISO-COST.

## 2. Что проверено в этой песочнице (реальные числа, не обещания)

`python3 test_delta.py` (numpy 2.4.6, float64, ε=1e-6, B=2, T=9, D=12):

| arm | max относит. \|аналитика − FD\| | «чанк за чанком == целиком» | float32 чанк-vs-рекурр |
|---|---|---|---|
| dddecay | **1.3e-09** | 0.00e+00 | 1.2e-07 |
| rot | **6.4e-10** | 0.00e+00 | 4.5e-08 |
| delta | **1.0e-09** (все 9 параметров + X) | 6.7e-16 | — |

Его планка из MATH.md §11 — 1e-5 на конечных разностях; здесь на четыре порядка лучше,
потому что эталон и градиент выведены из одной записи и ни разу не «ускорялись в обход
спецификации».

Прочие проверки: `delta` при T=2048 — `finite=True`, `|S|` от 0.00 до **1.01** (не растёт);
чанк-форма даёт `max|Δ|` ~2e-16 при C ∈ {1,3,4,128}.

### Два бага, которые поймал паритет, а не человек

1. **Ненормализованные ключи в δ-правиле.** Без `k ← k/‖k‖` собственный вектор
   `(I − β k kᵀ)` равен `1 − β‖k‖² ≈ 1 − 6 = −5`; состояние расходилось (NaN к T≈2000).
   l2-нормализация в DeltaNet — не косметика, а условие устойчивости. Плюс: `np.maximum(‖k‖,1e-12)`,
   а **не** `‖k‖ + eps` — сдвиг меняет функцию, и FD честно показывает 7.8e-08 вместо 1e-09.
2. **Отрицательный индекс в ядре чанка.** `W1[t,i] = kern[t−i]` при `i>t` молча брал элемент
   с конца массива. C=1 совпадало, C≥3 расходилось на 0.6–0.8. В `for`-цикле по t такого
   не видно вообще: баг жил только в «быстрой» версии.

### Скорость в numpy (B=4, D=192, fwd)

| | T=96 | T=1024 |
|---|---|---|
| dddecay рекуррентно | 2.5 мс | 13.6 мс |
| dddecay чанк C=64 | 33.8 мс | 326.3 мс |
| rot рекуррентно | 2.1 мс | 20.0 мс |
| rot чанк C=64 | 15.0 мс | 197.2 мс |
| delta рекуррентно | 93.9 мс | 989.1 мс |

**На CPU рекуррентная форма быстрее чанковой в 5–15×** — чанковка покупает параллелизм
ценой C× MAC, что имеет смысл только на GPU (там цикл по T убивает SM). Это ровно его
наблюдение про «потоковый EMA ≡ оконному», продолженное на новые миксеры: **инференс —
рекуррентно, обучение на T4 — чанками**. Для `delta` в numpy рекуррентно неприемлемо
(94 мс на 384 токена), ему нужен чанк-ядер в WY-форме (см. §4) — это следующий кусок работы.

## 3. Интеграция в его код (эскиз, минимальный дифф)

```python
# nano_lc.py: вместо ветки `a = sigmoid(th)` внутри ema_mix
if mixer == "ema":      # CTRL — без изменений, побитовый контроль
    a = sigmoid(th)
elif mixer == "dddecay":
    a = sigmoid(x @ Wa + ba)             # +D² MAC, состояние не растёт
elif mixer == "rot":                     # h — (B,2,D) вместо (B,D)
    h1, h2 = h[..., 0], h[..., 1]
    h = stack([rho*(c*h1 - s*h2), rho*(s*h1 + c*h2)], -1) + g*x
elif mixer == "delta":  # только при T>=512; состояние (B,D,D)
    ...
```

Что добавить в `--profile`-счётчик, иначе A/B нечестный: MAC и параметры **миксера** по
таблице §1. Его брекет (`kaggle/bracket.py`, rungs 60/200/500/1500, CTRL не выбывает)
переносится как есть: `ctrl = ema`, arms = `dddecay`, `rot`; латин-гиперкуб по
{lr, mulr, ssfull} — общий для всех трёх, чтобы сравнение было по миксеру.

Метрика решения — только **iso-quality по цене обучения** (его же метр ×2.4–2.6 для EMA
против attention), а не «PPL после фиксированного числа шагов»: A добавляет 37k MAC/токен,
и без равенства стоимости это будет спор о размере, а не о механизме.

## 4. Что ещё не сделано (по порядку ценности)

1. **`delta` в чанк-форме (WY-представление)** — без него arm нельзя учить. Формула на чанк:
   `T = (I + diag(β̃) K̃ K̃ᵀ)⁻¹` (нижняя треугольная, решается за O(C²D)),
   `ũ = T diag(β) v`, `S_{chunk} = S_prev ⊙ decay + K̃ᵀ ũ`. Градиент — из эталона, как здесь.
2. **Прогон при T=512–2048** на его же паре attn-vs-mixer — единственная проверка, что его
   ×2.4–2.6 переживёт смену T; там же `delta` впервые становится дешевле attention.
3. **state-tracking probe** (чётность / парность / «повтори последнюю букву») — `rot` делает
   ставку ровно на это; если probe не двигается, arm B мёртв и это надо записать как
   отрицательный результат (у него этот жанр уже отлажен).
4. Гибрид 3:1 (KDA-структура: 3 линейных слоя на 1 attention) — но это уже его «своя линия»,
   и цена входа выше: L=4, т.е. 1 слой из 4.

## 5. Ожидания (зарегистрированы ДО прогонов, чтобы нельзя было подогнать)

- A `dddecay`: val-PPL не хуже CTRL при ≤ +15 % MAC блока; выигрыш — на длинных хвостах
  и на probe. Если хуже CTRL — значит `th`-параметр у него уже выучил «нужное» затухание,
  и data-dependence на 3M-модели просто не на что опереться: записать и закрыть.
- B `rot`: по probe (чётность) — минимум ×2 улучшение при ≤ +0.5 % MAC; на val-PPL
  правдоподобно в пределах шума на T=96 и выигрыш на T≥512.
- C `delta`: при T=96 ожидаем **проигрыш** по iso-cost (он там 1.33× attn) — это и есть
  фальсификатор: если он при T=96 всё равно выигрывает у EMA изо-качество, то память
  важнее FLOPs и весь план «дешёвый миксер» надо пересматривать в сторону D²-классов.
